# 启动指南

> 本文说明「全功能启用」时的完整启动流程、服务依赖先后顺序,并重点介绍 Docker 部署。
> 覆盖服务:Redis、ChromaDB Server、LangFuse、embed-server、rerank-server、api-server、frontend、main(Streamlit)。

---

## 一、服务全景

| 层级 | 服务 | 端口 | 作用 | 开关/依赖 |
|------|------|------|------|-----------|
| 基础设施 | **Redis** | 6379 | 检索缓存 + 限流令牌桶 | 缺失则降级关闭(缓存跳过/限流放行) |
| 基础设施 | **ChromaDB Server** | 8100 | 向量库服务化(多实例共享) | `CHROMA_SERVER_URL` 空=本地 PersistentClient |
| 基础设施 | **LangFuse** + Postgres | 3000 | 全链路可观测 | `LANGFUSE_ENABLED=False` 需手动开 |
| 模型服务 | **embed-server** | 8001 | 嵌入模型独立服务(420MB) | `EMBED_SERVER_URL` 空=内嵌加载 |
| 模型服务 | **rerank-server** | 8002 | 重排模型独立服务(568MB) | `RERANK_SERVER_URL` 空=内嵌加载 |
| 权限后端 | **api-server** | 8000 | JWT 鉴权 / 用户 / 分组 / 用户级限流 | 登录必须 |
| 应用 | **frontend** (Vue3) | 5173 | 管理后台 | 可选 |
| 应用 | **main** (Streamlit) | 8501 | 对话界面(入口) | 最终入口 |

## 二、端口规划(避坑)

| 服务 | 端口 | 说明 |
|------|------|------|
| api-server | **8000** | FastAPI 权限后端 |
| embed-server | **8001** | 嵌入模型 |
| rerank-server | **8002** | 重排模型 |
| ChromaDB Server | **8100** | ⚠️ 不能用 8000——已被 api-server 占用 |
| Redis | 6379 | 默认 |
| LangFuse | 3000 | 默认 |
| frontend | 5173 | Vite 默认 |
| main (Streamlit) | 8501 | Streamlit 默认 |

> **关键坑**:`CHROMA_SERVER_URL` 的示例端口曾误写为 `:8000`,与 api-server 撞车。现已统一改为 **8100**。

## 三、依赖关系(决定先后顺序)

```
Redis ─────────────┐
ChromaDB Server ───┤   ← 第 1 层:基础存储/中间件(最先起)
LangFuse ──────────┘
        │
        ▼
embed-server / rerank-server   ← 第 2 层:模型服务(等模型加载完)
        │
        ▼
api-server (:8000)             ← 第 3 层:权限后端(登录依赖它)
        │
        ▼
frontend (:5173) + main (:8501)  ← 第 4 层:应用(最后起)
```

**核心链**:`main` 的 `depends_on` 要求 api-server / embed-server / rerank-server 三者 `healthy` 后才启动;登录依赖 api-server;缓存/限流依赖 Redis。

## 四、启动方式选择

| 场景 | 方式 |
|------|------|
| 本地开发 / 快速验证 | **手动分层启动**(见第五节) |
| 生产 / 多实例 / 稳定部署 | **Docker 编排**(见第六节,重点) |
| 只想对话、不折腾权限 | `streamlit run app.py` 一条命令(但登录会失败,见第八节坑 1) |

## 五、手动启动(本地开发,分层)

### 第 1 层:基础设施

```powershell
# ① Redis(缓存 + 限流)
docker run -d --name redis -p 6379:6379 redis

# ② ChromaDB Server(向量库服务化,⚠️ 端口用 8100)
docker run -d --name chromadb -p 8100:8000 chromadb/chroma
# 或本地 CLI:chroma run --path ./chroma_db --port 8100

# ③ LangFuse(可观测,可选)
docker compose -f docker-compose.langfuse.yml up -d
# 首次进 http://localhost:3000 注册 → 建 project → 拿 pk/sk 填 .env
```

### 第 2 层:模型服务

```powershell
cd d:\VsCode\AI\rag_assistant
venv\Scripts\activate.bat
python embed_server.py      # → :8001,等 /ready 返回 loaded
python rerank_server.py     # → :8002,冷启动 10-30s
```

### 第 3 层:权限后端

```powershell
uvicorn api_server:app --port 8000
```

### 第 4 层:应用

```powershell
cd frontend && npm run dev          # 管理后台 → :5173
# 另开终端
streamlit run app.py                # 对话界面 → :8501
```

## 六、Docker 部署(重点)

### 6.1 设计思想:一个镜像,四种角色

项目用 **单一 Dockerfile** 构建出 `rag-assistant` 一个镜像,由 `docker-compose.yml` 用不同 `command` 启动成 4 个服务。这样:

- **依赖只装一次**:Python 依赖、torch/onnxruntime 运行时库全部固化进镜像层。
- **模型权重不重复**:模型缓存通过 volume 挂 D 盘,多服务共享同一份 420MB + 568MB 模型。
- **改代码不重装依赖**:Dockerfile 先 `COPY requirements.txt` + `pip install`,再 `COPY . .`,利用构建缓存层。

[Dockerfile](Dockerfile) 关键点:

```dockerfile
FROM python:3.12-slim            # 轻量基础镜像
RUN apt-get install ... libgomp1 libglib2.0-0 tini   # OpenMP 运行时 + tini 收孤儿子进程
COPY requirements.txt . && pip install ...           # 先装依赖(缓存层)
COPY . .                                              # 再复制代码
ENV HF_ENDPOINT=https://hf-mirror.com HF_HOME=/root/.cache/huggingface
ENTRYPOINT ["tini", "--"]        # tini 作 PID 1,正确回收 mcp_server stdio 子进程
CMD ["python", "mcp_server.py"]  # 默认命令,docker-compose 用 command 覆盖
```

### 6.2 docker-compose.yml:4 服务编排

[docker-compose.yml](docker-compose.yml) 编排以下 4 个服务(共用同一镜像):

| 服务 | command | 端口 | 说明 |
|------|---------|------|------|
| `api-server` | `uvicorn api_server:app` | 8000 | 权限后端 |
| `embed-server` | `python embed_server.py` | 8001 | 嵌入模型 |
| `rerank-server` | `python rerank_server.py` | 8002 | 重排模型 |
| `main` | `streamlit run app.py` | 8501 | 对话界面 |

### 6.3 依赖与健康检查机制

Docker 的启动顺序**不是靠命令行顺序**,而是靠 `depends_on` + `healthcheck`:

```yaml
main:
  depends_on:
    api-server:      { condition: service_healthy }
    embed-server:    { condition: service_healthy }
    rerank-server:   { condition: service_healthy }
```

- `embed-server` / `rerank-server` 的 healthcheck 打 `/ready` 接口,`retries: 30` 给足模型冷启动时间(420MB / 568MB)。
- `main` 要等上面三个都 `healthy` 才启动,避免「模型没加载完就收到检索请求 → 首查超时」。
- 环境变量注入跨容器调用:`main` 里 `EMBED_SERVER_URL=http://embed-server:8001`、`API_SERVER_URL=http://api-server:8000`,**用服务名而非 localhost**,这正是容器网络与本地开发的最大差异。

### 6.4 数据卷(全部落 D 盘,遵守项目环境约定)

| volume | 作用 |
|--------|------|
| `D:/VsCode/AI/.cache/huggingface:/root/.cache/huggingface` | 模型缓存,多服务共享,只下载一次 |
| `./chroma_db:/app/chroma_db` | 向量库数据持久化到宿主机 |
| `./uploaded_docs:/app/uploaded_docs` | 上传文档持久化 |
| `./permission.db:/app/permission.db` | 权限数据库持久化 |
| `./.env:/app/.env` | 密钥配置 |

### 6.5 为什么 Docker 只编排 4 服务

`docker-compose.yml` **故意不包含** Redis、ChromaDB、LangFuse、frontend,原因:

| 服务 | 不纳入编排的原因 |
|------|-----------------|
| Redis | 官方 `redis` 镜像开箱即用,直接 `docker run` 或另起 compose |
| ChromaDB | 官方 `chromadb/chroma` 镜像,数据与主服务共用一个目录,独立管理更清晰 |
| LangFuse | 独立 `docker-compose.langfuse.yml`(含 Postgres),按需起停 |
| frontend | 开发态(Vite dev server),未做生产构建容器化 |

### 6.6 完整 Docker 部署步骤

```powershell
cd d:\VsCode\AI\rag_assistant

# ① 构建镜像(必须先于 compose up)
docker build -t rag-assistant .

# ② 起 4 服务编排(自动处理健康检查 + 依赖顺序)
docker compose up -d

# ③ 补基础设施(编排之外,按需)
docker run -d --name redis -p 6379:6379 redis
docker run -d --name chromadb -p 8100:8000 chromadb/chroma
docker compose -f docker-compose.langfuse.yml up -d   # 可观测

# ④ 查看状态
docker compose ps
docker compose logs -f main          # 跟踪主服务日志
```

停止:

```powershell
docker compose down                  # 停 4 服务(保留数据卷)
docker compose down -v               # 连同数据卷一起删(慎用)
```

### 6.7 完整方案(所有功能全开)

```
docker build + docker compose up -d   →  4 应用/模型/权限服务
docker run redis                      →  缓存 + 限流
docker run chromadb (8100)            →  向量库服务化(需 .env 配 CHROMA_SERVER_URL)
docker compose langfuse               →  可观测(需 config 开 LANGFUSE_ENABLED)
npm run dev (frontend)                →  管理后台
```

## 七、.env 配置清单

「所有功能都启用」需补齐(不全只是「没启用」,不会崩):

```ini
GROQ_API_KEY=...                    # LLM(必须)
OPENWEATHER_API_KEY=...             # 天气
EDU_STUDENT_ID=...  EDU_PASSWORD=...# 教务
BAIDU_OCR_API_KEY=... SIMPLETEX_API_KEY=...  # 公式 OCR
LANGFUSE_PUBLIC_KEY=... LANGFUSE_SECRET_KEY=... LANGFUSE_HOST=http://localhost:3000
EMBED_SERVER_URL=http://localhost:8001
RERANK_SERVER_URL=http://localhost:8002
CHROMA_SERVER_URL=http://localhost:8100    # ⚠️ 8100,不是 8000
REDIS_HOST=localhost  REDIS_PORT=6379
```

config.py 里需手动改:`LANGFUSE_ENABLED = True`(默认 False)。
其余 `SEARCH_CACHE_ENABLED` / `RATE_LIMIT_ENABLED` / `CB_ENABLED` / `TOOL_PERMISSION_ENABLED` 已默认开。

## 八、常见坑

1. **只跑 `streamlit run app.py` 登录报「目标计算机拒绝」**:登录请求发 `http://localhost:8000/api/auth/login`,那是 api-server 的地址。必须额外启动 `uvicorn api_server:app --port 8000`。默认账号 `admin` / `admin123`。
2. **ChromaDB 端口撞车**:`CHROMA_SERVER_URL` 若配成 `:8000` 会与 api-server 冲突,统一用 **8100**。
3. **模型冷启动慢**:embed(420MB)/ rerank(568MB)首次加载 10-30s,`main` 健康检查在等它们 `ready`,没就绪前不要调检索。
4. **Redis 缺失是降级不是报错**:没起 Redis 时系统照常跑,但「缓存 / 限流」实际未生效——别以为起了就一定有缓存。
5. **容器内用服务名,不用 localhost**:Docker 网络里 `main` 通过 `http://embed-server:8001` 访问模型服务;本地开发才是 `localhost:8001`。
6. **改代码后重建镜像**:`docker compose up -d` 不会自动重新 build,改了代码要 `docker build -t rag-assistant .` 再 `up -d --force-recreate`。
