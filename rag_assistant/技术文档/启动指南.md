# 启动指南

> 本文只回答一件事：**怎么把项目跑起来**。先看第一节选路线。

---

## 一、选一条路线

| 你的情况 | 走哪条 | 起什么 |
|---------|--------|--------|
| **装了 Docker Desktop** | **A. Docker 一键** | 5 个容器：对话 + 权限 + 嵌入 + 重排 + Redis |
| **没装 Docker** / 改代码调试 | **B. 本地启动** | 对话界面 + 权限后端（模型在主进程内加载） |

> 不确定装没装？终端敲 `docker --version`——报 `'docker' is not recognized` 就是没装，走 B。

### A. Docker 一键

```powershell
cd d:\VsCode\AI\rag_assistant

copy .env.example .env              # ① 首次：生成配置，填上 GROQ_API_KEY
docker build -t rag-assistant .     # ② 构建镜像（首次或改代码后需重建）
docker compose up -d                # ③ 一键起全部核心服务
```

**首次启动需等 1-3 分钟**（模型冷启动：嵌入 420MB + 重排 568MB）。

```powershell
docker compose ps                   # 查看状态，等全部变成 healthy / running
docker compose logs -f main         # 跟踪主服务日志（Ctrl+C 退出，不影响容器）
```

停止：`docker compose down`（保留数据）／`docker compose down -v`（⚠️ 连数据卷一起删）

> ⚠️ `.env` 文件**必须存在**——compose 会把它挂进容器，若本地没有该文件，Docker 会创建一个同名**目录**导致配置读取失败。
>
> **从旧版本升级**：把已有数据移入 `runtime_data\`，否则容器里用户与记忆都是空的：
> ```powershell
> move permission.db runtime_data\    # 用户/角色/分组（不迁则重建默认 admin）
> move memory.db     runtime_data\    # 长期记忆
> ```

### B. 本地启动（没装 Docker 也能跑）

```powershell
cd d:\VsCode\AI\rag_assistant
venv\Scripts\activate.bat

# 终端 1：权限后端（登录依赖它）
uvicorn api_server:app --port 8000

# 终端 2：对话界面
streamlit run app.py
```

访问 http://localhost:8501，账号 `admin` / `admin123`。

**没有 Docker 时的差异**——功能都能用，只是少两样：

| 项 | 状态 |
|----|------|
| 对话 / RAG 检索 / 长期记忆 / 权限 / 工具调用 | ✅ 可用 |
| 模型（嵌入 420MB + 重排 568MB） | ✅ 主进程内加载（首次查询慢 10-30s） |
| 检索缓存 + 限流 | ⚠️ **降级关闭**（依赖 Redis）。日志会打 `⚠️ Redis 不可用，限流降级关闭（fail-open 放行）`——预期行为，不影响功能 |
| 管理后台 | ⚠️ 本地未构建前端，需 `cd frontend && npm run dev`（→ :5173） |
| LangFuse 可观测 | ❌ 未启用（可选功能） |

> 只想要缓存/限流？装 Docker 后单跑 `docker run -d --name redis -p 6379:6379 redis` 即可，不必起整个编排。
> 想把模型拆成独立服务（多实例共享权重）？见**第八节**的完整分层启动。

## 二、启动后访问什么

| 地址 | 是什么 | 说明 |
|------|--------|------|
| **http://localhost:8501** | **对话界面**（Streamlit） | 主入口，在这里提问 |
| **http://localhost:8000** | **管理后台**（Vue3） | 用户/角色/分组/文档/审计管理 |

> 两个界面都**必须登录**（fail-closed 登录守卫）。默认账号 **`admin` / `admin123`**。
> ⚠️ 登录失败会提示「目标计算机拒绝连接」——说明 api-server（:8000）没起来。

**管理后台不需要单独启动**：前端在 `docker build` 阶段已编译进镜像，由 api-server 在 `:8000` 直接托管（`frontend/dist` + SPA 路由兜底）。仅当你要**改前端代码**热更新时，才需要 `cd frontend && npm run dev`（→ :5173）。

## 三、`docker compose up -d` 起了哪些容器

| 容器 | 端口 | 作用 |
|------|------|------|
| `redis` | 6379 | 检索缓存 + 限流令牌桶 |
| `api-server` | 8000 | JWT 鉴权 / 用户 / 分组 / 用户级限流 / 前端静态文件 |
| `embed-server` | 8001 | 嵌入模型服务（420MB） |
| `rerank-server` | 8002 | 重排模型服务（568MB） |
| `main` | 8501 | 对话界面（含 MCP 子进程 + 向量库） |

**启动顺序由 `depends_on` + `healthcheck` 保证**，不是命令行顺序：

```
redis ────────────────┐
api-server ───────────┤
embed-server ─────────┼─→ main（等全部 healthy 才启动）
rerank-server ────────┘
```

`embed-server` / `rerank-server` 的 healthcheck 打 `/ready` 且 `retries: 30`，给足模型冷启动时间——避免「模型没加载完就收到检索请求 → 首查超时」。

## 四、没包含的模块（以及什么时候才需要）

默认编排**故意不含**下面两个，因为单机跑不需要：

| 模块 | 不纳入的原因 | 什么时候才要起 |
|------|-------------|---------------|
| **ChromaDB Server** | 单机用容器内本地向量库（PersistentClient）即可，起独立服务反而要多维护一份数据一致性 | 需要**多实例**共享向量库时。见第六节 |
| **LangFuse** | 需手动注册账号、拿密钥，无法真正"一键" | 要看全链路 trace 时。见第六节 |

## 五、让功能全开：`.env` 配置清单

Docker 下 **compose 已自动注入** `EMBED_SERVER_URL` / `RERANK_SERVER_URL` / `API_SERVER_URL` / `REDIS_HOST`，**不需要**写进 `.env`。

`.env` 里按需补（项目已提供模板：**`copy .env.example .env`**，含全部键名与注释）：

```ini
GROQ_API_KEY=...                      # LLM（必须，否则对话不可用）
OPENWEATHER_API_KEY=...               # 天气工具
EDU_STUDENT_ID=...  EDU_PASSWORD=...  # 教务工具
BAIDU_OCR_API_KEY=...  BAIDU_OCR_SECRET_KEY=...   # 公式识别
SIMPLETEX_API_KEY=...                 # 公式识别备选
ALERT_WEBHOOK_URL=...                 # 熔断告警推送到钉钉/飞书（可选）
LANGFUSE_PUBLIC_KEY=... LANGFUSE_SECRET_KEY=... LANGFUSE_HOST=http://localhost:3000  # 可观测（可选）
```

**默认已开启**（config.py），无需配置：检索缓存 / 限流 / 熔断 / 工具鉴权 / 长期记忆 / 混合检索 / 查询改写 / 重排 / 独立 Judge / 会话摘要压缩。
**需手动开**：`LANGFUSE_ENABLED = True`（默认 False，且要先起 LangFuse 服务）。

## 六、可选模块：按需启动

### 6.1 可观测（LangFuse）

```powershell
docker compose -f docker-compose.langfuse.yml up -d      # → http://localhost:3000
```

首次进 http://localhost:3000 注册账号 → 建 project → 拿 `pk-lf-...` / `sk-lf-...` 填进 `.env` → 把 `config.py` 的 `LANGFUSE_ENABLED` 改为 `True`。

### 6.2 向量库服务化（ChromaDB Server）

**仅在需要多实例共享向量库时使用。**

```powershell
docker run -d --name chromadb -p 8100:8000 chromadb/chroma
```

然后在 `.env` 加：`CHROMA_SERVER_URL=http://localhost:8100`

> ⚠️ **端口必须用 8100**——8000 已被 api-server 占用。
> ⚠️ 切换前确认本地 `chroma_db/` 无进程占用：本地客户端与服务端**不要同时打开同一目录**。

## 七、怎么确认启动成功

```powershell
# ① 容器状态：5 个都应是 running / healthy
docker compose ps

# ② 模型服务就绪（返回 loaded 才算好）
curl http://localhost:8001/ready
curl http://localhost:8002/ready

# ③ 权限后端就绪
curl http://localhost:8000/openapi.json

# ④ 对话界面就绪
curl http://localhost:8501/_stcore/health
```

再看一眼启动日志里有没有这几行（都为 INFO/WARNING，无 ERROR 即正常）：

```
[UnifiedAgent] 首次预热完成
   🚦 限流器就绪: Redis redis:6379
   记忆: 初始化完成
```

若看到 `⚠️ Redis 不可用，限流降级关闭（fail-open 放行）`，说明 Redis 没连上——此时**缓存和限流实际未生效**（系统照跑，但别以为起了就有）。

## 八、本地完整分层启动（把模型拆成独立服务）

比 **1.B 的极简启动**多起两个模型服务进程。适合：多实例共享模型权重、不想每次查询都等主进程加载模型、或要改后端代码（免去重建镜像）。**四层按序启动**：

```powershell
cd d:\VsCode\AI\rag_assistant
venv\Scripts\activate.bat
```

**第 1 层：基础设施**

```powershell
docker run -d --name redis -p 6379:6379 redis          # 缓存 + 限流（可跳过，见下）
# 其余两项按需：LangFuse 见 6.1；ChromaDB Server 单机不需要
```

> 没有 Docker 可**整层跳过**——缓存/限流会降级关闭（fail-open），功能不受影响。

**第 2 层：模型服务**（各自一个终端，冷启动 10-30s）

```powershell
python embed_server.py       # → :8001
python rerank_server.py      # → :8002
```

**第 3 层：权限后端**

```powershell
uvicorn api_server:app --port 8000
```

**第 4 层：应用**

```powershell
streamlit run app.py         # → :8501
```

> 本地模式下 `.env` 需自己写 `EMBED_SERVER_URL=http://localhost:8001` / `RERANK_SERVER_URL=http://localhost:8002`（容器内用服务名，本地用 localhost——这是两者最大差异）。
> 本地不构建前端时，`:8000` 不提供管理后台（`frontend/dist` 不存在），需 `cd frontend && npm run dev` 走 :5173。

## 九、Docker 设计说明

**一个镜像，四种角色**：单一 `Dockerfile` 构建 `rag-assistant` 镜像，`docker-compose.yml` 用不同 `command` 启动成 api-server / embed-server / rerank-server / main。好处：

- **依赖只装一次**：Python + torch/onnxruntime 全部固化进镜像层
- **模型权重不重复**：HF 缓存挂在 D 盘，多服务共享同一份 420MB + 568MB 模型，只下载一次
- **改代码不重装依赖**：Dockerfile 先 `COPY requirements.txt` + `pip install`，再 `COPY . .`，利用构建缓存层

**构建要点**（[Dockerfile](Dockerfile)）：

```dockerfile
FROM node:20-slim AS frontend-builder   # 阶段 1：编译 Vue3 → dist
FROM python:3.12-slim                   # 阶段 2：Python 运行时
RUN apt-get install libgomp1 libglib2.0-0 tini   # OpenMP 运行时 + tini 收孤儿子进程
ENTRYPOINT ["tini", "--"]               # tini 作 PID 1，正确回收 mcp_server stdio 子进程
```

**数据卷（全部落 D 盘，遵守项目环境约定）**：

| volume | 作用 |
|--------|------|
| `D:/VsCode/AI/.cache/huggingface` | 模型缓存，多服务共享，只下载一次 |
| `D:/VsCode/AI/.cache/redis` | Redis 持久化（AOF） |
| `./chroma_db` | 向量库数据 |
| `./uploaded_docs` | 上传的文档 |
| `./runtime_data` | **全部运行产物**（见下） |
| `./.env` | 密钥配置 |

**运行产物持久化**：容器内生成的运行产物统一落到 `runtime_data/`，`docker compose down` 后不丢。
`api-server` 与 `main` 各挂载一次该目录（写入的文件互不重叠）：

| 文件 | 写入方 | 用途 |
|------|--------|------|
| `permission.db` | api-server | 权限数据库（用户/角色/分组） |
| `memory.db` | main | 长期记忆库 |
| `tool_audit.jsonl` | main | 工具调用审计（`agent_eval.py` 评测数据源） |
| `token_log.jsonl` | main | Token 用量与成本历史 |
| `qa_log.jsonl` | main | 问答日志 |
| `alert.log` | main | 熔断告警记录 |
| `bm25_index.pkl` | main | BM25 索引（丢了也会自动重建） |
| `formula_cache.json` | main | 公式识别缓存 |

实现方式：`config.py` 的 `RUNTIME_DATA_DIR` 环境变量（compose 注入 `/app/runtime_data`），由 `runtime_path()` 统一解析各产物路径。
**不设该变量时各文件仍用原位置**——所以本地开发（不用 Docker）行为完全不变。

> ⚠️ **从旧版本升级到 Docker 部署，务必先迁移数据**：
> ```powershell
> move permission.db runtime_data\    # 不迁 → 用户/角色/分组丢失（会重建默认 admin）
> move memory.db     runtime_data\    # 不迁 → 长期记忆从空开始
> ```

## 十、常见坑

1. **登录报「目标计算机拒绝」**：api-server 没起。Docker 下看 `docker compose ps`；本地下需单独 `uvicorn api_server:app --port 8000`。
2. **ChromaDB 端口撞车**：`CHROMA_SERVER_URL` 若配成 `:8000` 会与 api-server 冲突，统一用 **8100**。
3. **模型冷启动慢**：embed（420MB）/ rerank（568MB）首次加载 10-30s，`main` 的健康检查在等它们 ready，没就绪前别调检索。
4. **Redis 缺失是静默降级**：没起 Redis 系统照跑，但缓存/限流**实际未生效**。且限流器是进程内单例，初始化失败后会**永久保持放行**直到重启——所以 compose 里 `api-server`/`main` 都 `depends_on` 了 redis 的 healthy。
5. **容器内用服务名，不用 localhost**：Docker 网络里 `main` 通过 `http://embed-server:8001` 访问模型服务；本地开发才是 `localhost:8001`。compose 已自动注入，无需手写。
6. **改代码后必须重建镜像**：`docker compose up -d` 不会自动 rebuild，要 `docker build -t rag-assistant .` 再 `docker compose up -d --force-recreate`。
7. **`.env` 文件必须先存在**：compose 把 `./.env` 挂进容器，若本地没有该文件，Docker 会创建一个**同名目录**，导致容器读取配置失败。首次克隆项目后先 `copy .env.example .env` 并填上 `GROQ_API_KEY`。
8. **不要用 `docker compose down -v`**：`-v` 会删除数据卷，`.env` 之外挂载的数据虽在宿主机上，但卷清理可能影响 Redis 持久化数据。清理容器用 `down` 即可。
