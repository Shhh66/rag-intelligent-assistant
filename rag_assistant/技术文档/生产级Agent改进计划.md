# 生产级 Agent 改进计划（校招聚焦版）

> 本文定位：**面试叙事 + 落地优先级**，不是全量工程清单。
> 核心原则一句话：**让面试官看到「你一个人把核心链路做成了能上线的样子」+「你知道完整生产系统还缺什么」**——这比堆砌六个半成品强得多。
>
> 策略：**认知全覆盖 + 做深 2-3 块 + 其余讲设计**。校招不要求交付完整生产系统（面试官也不信应届生做全套负载均衡集群），他要看的是**生产级认知 + 能落地其中几块 + 有深度思考**。

---

## 一、认知框架：六大模块 + 四层架构（面试必讲，需能画图）

### 1.1 六大核心模块（每块一句话说清它解决什么生产问题）

| 模块 | 一句话职责 | 解决的生产问题 |
|------|-----------|---------------|
| **核心执行引擎** | 跑 Agent Loop（推理→行动→观察循环），调度工具、回收结果、组装上下文 | 模型 API 超时、工具失败、返回格式异常时的健壮性 |
| **模型网关层** | 封装大模型 API 交互 | 多模型路由、负载均衡、多 Key 轮转、故障切备用、限流、Token 监控 |
| **工具管理层** | 工具注册/发现/权限/执行 | 沙箱隔离、超时控制，防单工具故障拖垮系统 |
| **记忆管理层** | 短期（上下文/历史压缩）+ 长期（持久化+向量检索） | 决定长任务、跨会话任务能力 |
| **可观测性层** | 全链路追踪 + 监控告警 | 生产系统排查问题的基础 |
| **安全层** | 输入过滤 + 输出审核 + 工具鉴权 + 数据隔离 | 防注入、防泄露、防越权 |

### 1.2 四层架构

```
接入层    API 网关 / WebSocket / 消息队列        ← 高并发接入、实时通信、异步任务
核心层    Agent 引擎 + 模型网关 + 工具管理 + 记忆管理  ← 编排调度、智能决策、上下文维护
基础设施层  向量库 / 关系库 / 缓存 / 对象存储      ← 数据持久化
运维层    链路追踪 / 日志 / 监控告警 / 成本分析    ← 全链路可观测
```

## 二、项目现状：内核真实、外围缺失

**判定：半生产级——核心链路已做成"能上线"的样子，外围四块（模型容灾、安全防线、可观测告警、异步化）尚缺。**

### 2.1 已做深（可演示、可量化、代码级可验证）

| 能力 | 代码证据 | 面试讲法 |
|------|---------|---------|
| 五阶段 ReAct 决策引擎 + 并行调度 + 死循环检测 | `decision_engine.py`、`scheduler.py`、`unified_agent.py` | 自研替代 LangChain AgentExecutor，三点硬优势：并行、结构化输出、非 LLM 护栏 |
| 熔断器三态状态机（per-destination + HALF_OPEN 探针） | `circuit_breaker.py` | fail-closed 语义，与限流 fail-open 正交 |
| 限流器 Redis Lua 原子令牌桶 | `rate_limiter.py` | 两层限流，Lua 防竞态 |
| 结构化输出降级链 | `decision_engine.py` | json_schema→json_object→错误重试→兜底直答 |
| 工具鉴权 fail-closed + RBAC + JWT | `scheduler.py`、`api_server.py` | 请求级权限透传，无文件共享 |
| 长期记忆（Chroma 语义 + SQLite 结构化，按用户隔离） | `long_term_memory.py` | 去重/权重/时间衰减 |
| 链路追踪（trace_id 贯穿 + 审计 JSONL + LangFuse） | `tool_audit.py`、`observability.py` | trace_id 打通审计与可观测 |

### 2.2 半成品（有底子、差一环）

| 块 | 已有 | 缺 |
|----|------|-----|
| 可观测性 | trace_id + 审计 + LangFuse + token 记录 | **指标采集 + 告警** |
| 成本控制 | token 记录 + 检索缓存 | **归因分析 + 动态选模 + token 预算** |
| 记忆管理 | 长期记忆完整 | 短期记忆 **LLM 摘要压缩**（现在是简单截断） |
| 安全 | 工具鉴权 + 数据隔离 + 入参脱敏 | 输入注入检测 + 输出审核 |

### 2.3 空白（只能讲设计）

模型网关（多 key 轮转/故障切备用）、监控告警、异步任务/消息队列、多租户完整 RBAC。

## 三、取舍决策：做深 2-3 块，其余讲设计

选择标准：**面试出现频率 × 可量化程度 ÷ 实现成本**。

```
图例：■ 做深（可演示可量化）　■ 讲清楚（已有，不补）　■ 讲设计（画图讲方案）
```

| 块 | 决策 | 理由 |
|----|------|------|
| **① 可观测性** | ■ 做深（补指标+告警） | trace 底子已有，只差最后两环，成本最低杠杆最高，直接回应"Demo vs 生产" |
| **② 成本控制** | ■ 做深（简化模型网关） | 面试高频、可量化"成本降 X%"，已有 JUDGE_MODEL 可配不同模型的雏形 |
| **③ 安全 Guardrails** | ■ 做深（可选加分） | 输入注入检测 + 输出审核，成本低、故事性强，有余力再上 |
| **④ 执行引擎** | ■ 讲清楚（不补） | 异常处理已扎实（超时/重试/熔断/格式降级），重投入是浪费，把已有能力讲深即可 |
| **⑤ 记忆管理** | ■ 讲清楚（补一小角） | 长期记忆已完整，只缺短期摘要压缩 |
| **⑥ 网关/消息/多租户** | ■ 讲设计 | 一人做全套既不真实又耗时，能画架构图讲清"如果上线怎么设计"反而显全局视野 |

## 四、做深清单（优先级最高，可演示可量化）

### 4.1 可观测性：补指标 + 告警（在已有 trace 底子上补最后两环）

**现状**：trace_id 贯穿 + 审计 JSONL + LangFuse 全链路追踪已有，缺的是**运行时指标 + 告警**。

**动作**：
1. 新增 `metrics.py`，暴露 Prometheus 风格 `/metrics`，采集：
   - 熔断状态（每 destination 的 CLOSED/OPEN/HALF_OPEN）
   - 限流触发次数（用户级/LLM 级）
   - 工具调用成功率、端到端延迟 P50/P99
   - LLM 调用次数与 Token 消耗
2. 接入 Grafana + 告警规则：熔断 OPEN 持续、5xx 率、延迟 P99 超阈值 → webhook 通知

**面试讲法**：*"我不只埋了 trace，还补了指标和告警——熔断打开、限流触发、端到端延迟都有实时指标，故障能自动告警而不是靠人盯日志。"*

### 4.2 成本控制：简化模型网关

**现状**：已有 `JUDGE_MODEL` 可配不同模型的雏形 + 检索缓存 + token 记录，缺**路由层**。

**动作**：
1. 新增 `model_gateway.py` 路由层，按任务难度分派模型：
   - 简单任务（意图判断、参数提取、技能匹配）→ 便宜小模型
   - 强推理（ReAct 决策、最终回答汇总）→ 大模型
2. 单任务 Token 预算：超上限强制终止，返回中间结果（现在是只有 80% 告警、不终止）
3. 缓存复用：相同参数的工具调用结果缓存（检索缓存已有，扩展到其他可缓存工具）

**量化目标**：成本降 X%（需实测对比——同一批 query 走"全大模型"vs"路由分派"的 Token 费用差）。

**面试讲法**：*"我做了一个简化模型网关：意图判断和参数提取这种简单任务走小模型，只有强推理才上大模型，再加上单任务 token 预算和缓存复用，成本降了 X%。"*

### 4.3 安全 Guardrails（可选，有余力再上）

**动作**：
1. 输入层：Prompt 注入检测（规则 + 小模型分类），命中则拒绝或降级
2. 输出层：PII/敏感词审核，命中则脱敏或拦截

**面试讲法**：*"工具鉴权和数据隔离我已经做了，还补了输入注入检测和输出审核，防越狱和敏感信息泄露。"*

## 五、讲设计清单（只画图讲方案，不实现）

这些是"基础设施叙事"，面试时**能画出架构图、讲清方案**即可，不做全套（面试官也不信应届生做全套）。

### 5.1 完整模型网关（多 key 轮转 + 故障切换）
- 多 Key 轮转：多 API Key 轮换，规避单 Key 限流
- 主模型熔断后切备用模型（现在是"快速失败"，缺降级通道）
- 负载均衡：多实例分发

### 5.2 异步任务 + 状态机
- 长任务异步化：提交返回 task_id，后台执行
- 状态机：创建 → 排队 → 执行中 → 成功/失败/超时，持久化支持断点续跑
- WebSocket/SSE 推送进度

### 5.3 多租户 + 完整 RBAC
- 完整的多租户隔离、细粒度 RBAC、审计合规

**统一讲法**：*"完整生产系统还需要模型网关的故障切换、异步任务状态机、多租户隔离——这些我知道怎么做，但目前是单机形态，没到那个规模就不做全套。"*

## 六、面试叙事脚本

### 6.1 一句话定位

> "我基于 MCP 协议自研了一个 Agent 执行引擎，核心链路做到了能上线的程度——五阶段 ReAct 决策、工具并行调度、熔断限流、结构化输出约束、长期记忆、链路追踪都有；同时我清楚完整生产系统还缺什么——模型网关的容灾、监控告警、异步化、安全输入输出，这几块我知道怎么设计。"

### 6.2 被问「你怎么把它做成生产级的」

> 分三层回答：**认知全覆盖**（六大模块我都清楚职责）、**做深两块**（可观测性补了指标告警、成本控制做了简化模型网关）、**其余讲设计**（网关/消息/多租户能画图讲方案）。突出"我不是堆模块，而是知道哪些该做深、哪些该讲设计"。

### 6.3 被问「你这项目缺什么」（诚实回答，反显思考深度）

> "缺的是模型容灾——现在是单一 DeepSeek，熔断后只能快速失败，没有切备用模型的降级通道；还有监控告警和异步化。但我清楚这些怎么补，只是单机形态还没到那个规模。"
