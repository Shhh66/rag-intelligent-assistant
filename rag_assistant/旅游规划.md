# 旅游规划 —— 天气 + 联网搜索 双工具组合

> 本文档规划为 Agent 新增**联网搜索能力**,与现有天气查询组合为"旅游行程规划"场景。**方案待审阅,本轮不实现代码。**

---

## 一、现状

| 能力 | 现状 |
|------|------|
| 天气查询 | ✅ `query_weather`(OpenWeatherMap API),返回温度/湿度/风速/天气描述 |
| 联网搜索 | ❌ 无。Agent 遇到旅游攻略/景点推荐/美食攻略等问题时无法获取最新信息 |
| Skill 组合 | ✅ `weather_advice` Skill(根据天气给穿衣/出行建议)已存在 |

**缺口**:Agent 能告诉你"南京 15°C 多云",但无法告诉你"南京哪些景点值得去、什么美食必吃、三天怎么安排"。

---

## 二、目标

用户自然语言提问 → Agent 自主并行调用"天气 + 搜索" → 综合生成行程规划:

```
用户: "我下周去南京玩三天,帮我规划一下"
  → Agent 判断意图:需要天气 + 攻略
  → 并行调用(自研 ReAct 的并行能力):
      query_weather("南京")        → 温度/湿度/风速
      web_search("南京三日游攻略 景点 美食 交通") → 攻略
  → 汇总生成:
      "南京 3月12-14日 8~18°C 多云。
       穿着:薄外套+长裤,早晚温差大。
       推荐路线:
         Day1 中山陵→明孝陵→夫子庙(晚餐鸭血粉丝汤)
         Day2 南京博物院→总统府→老门东(小吃:糖芋苗)
         Day3 玄武湖→鸡鸣寺(樱花季) 下午返程
       贴士:周末景区人多,建议9点前到中山陵避免排队"
```

## 三、联网搜索接入方案

### 3.1 技术选型:DuckDuckGo Instant Answer API(零成本)

| 方案 | 费用 | 依赖 | 适用 |
|------|:---:|------|------|
| **DuckDuckGo**(`duckduckgo_search`) | 免费 | `pip install duckduckgo_search`(D盘) | ✅ 个人项目,零成本,无日限额 |
| SerpAPI/Serper.dev | 付费(100次/月免费) | HTTP API | 稳定但需注册 |
| 自建 SearXNG | 免费 | Docker 自部署 | 部署重,个人项目过度 |

**推荐 DuckDuckGo**:Python 库直接调 Instant Answer API,无需 Key,返回标题+摘要+URL,个人使用完全够。

### 3.2 新增工具代码(约 25 行)

```python
# 在 mcp_server.py 中注册

from duckduckgo_search import DDGS

@mcp.tool()
async def web_search(query: str, max_results: int = 5) -> str:
    """搜索互联网信息。获取最新旅游攻略、景点推荐、美食攻略、交通信息等。

    :param query: 搜索关键词(如"南京三日游攻略 景点推荐")
    :param max_results: 返回条数,默认5
    :return: 搜索结果(每条含标题、摘要、链接)
    """
    try:
        results = []
        with DDGS() as ddgs:
            for r in ddgs.text(query, max_results=max_results):
                results.append(
                    f"📌 {r['title']}\n"
                    f"   {r['body'][:200]}\n"
                    f"   🔗 {r['href']}"
                )
        return "\n\n".join(results) if results else "未找到相关结果"
    except Exception as e:
        return f"搜索失败: {e}"
```

### 3.3 旅游 Skill(封装天气+搜索并行)

```python
# skills/builtin/travel_planner.py

TRAVEL_PLANNER = {
    "name": "travel_planner",
    "description": "旅游行程规划:并行查询目的地天气与攻略,综合生成行程建议",
    "trigger_keywords": ["旅游", "去...玩", "行程", "攻略", "出行", "旅行",
                         "三日游", "玩几天", "去哪玩", "推荐景点", "想逛"],
    "steps": [
        {
            "tool": "query_weather",
            "args": {"city": "{city}"},
            "mode": "parallel",       # 与搜索同时发起
        },
        {
            "tool": "web_search",
            "args": {"query": "{city}{days}旅游攻略 景点推荐 美食 交通"},
            "mode": "parallel",
        },
    ],
    "post_prompt": (
        "请根据天气信息和搜索结果,为用户生成行程规划:\n"
        "1. 根据温度/湿度/风速 推荐穿着(薄/厚外套、防晒、雨具)\n"
        "2. 按天数排列景点(每半天 1-2 个,避免赶路)\n"
        "3. 推荐当地必吃美食\n"
        "4. 如有必要,提醒出行贴士(交通、避开高峰、门票预约)\n"
        "5. 景点和美食标注来源(📌来自XX攻略)\n\n"
        "【参数容错规则】\n"
        "- 用户没说天数 → 默认3天\n"
        "- 用户没说具体日期 → 默认按未来最近周末或下周计算\n"
        "- 城市不明确(如'去海边') → 反问城市,不强行规划"
    ),
}
```

## 六、风险与注意

- **DuckDuckGo 速率限制**:瞬时大量请求可能被限;个人使用无影响。若频繁请求,调低 `max_results`。
- **搜索结果质量**:中文搜索不如 Google,但对旅游攻略类问题(中文网站多)效果足够。
- **Agent 可能编造**:LLM 可能把搜索结果里不存在的景点编进去 → Skill 的 `post_prompt` 已加"基于搜索结果"约束;Prompt 护栏与目前 RAG 生成的防幻觉策略一致。
- **依赖 D 盘**:`duckduckgo_search` 装 D 盘 venv,遵守项目环境约定。

## 七、优化建议（更贴合学生项目 / 面试演示）

### 7.1 参数自动填充（一句话触发全流程）

当前 Skill 需要 `city` 和 `days` 两个参数。在 `post_prompt` 里加一步参数容错，不靠额外校验代码，纯靠 Prompt：

```
补充规则：
- 如果用户没说天数，默认按 3 天规划
- 如果用户没说具体日期，默认按"未来最近一个周末"或"下周"计算
- 如果城市不明确（如"去海边玩"），反问城市,不强行规划
```

**效果**：用户只需说"帮我规划下杭州的行程",Agent 自动补齐 3 天+未来天气,不会因缺参数卡住。**演示时随便一句话就能跑通,不翻车。**

### 7.2 绑定长期记忆做个性化（一个 Demo 展示两个模块）

与项目已有的 `长期记忆.md` 联动,成本极低:

- 长期记忆里有"用户喜欢吃辣、偏好户外景点"→ 生成行程时自然筛选湘菜/川菜馆、推荐徒步/登山类景点
- 长期记忆里有"已去过南京中山陵"→ 规划时自动避开,推荐未去过的景点
- 长期记忆里有"预算有限、学生党"→ 优先免费景点、推荐青旅

**面试加分**:一个"帮我规划杭州行程"的 Demo,同时展示了联网搜索 + 长期记忆两个模块的联动——不是孤立的工具堆砌,而是**记忆让服务更懂你**。

### 7.3 准备兜底方案（防 DuckDuckGo 不稳定）

DuckDuckGo 中文搜索结果质量偶有波动。建议两层兜底:

**兜底 1:本地内置热门城市精简攻略**(硬编码 5-8 个热门城市的 3-5 个必去景点,约 50 行字典):
```python
_FALLBACK_GUIDES = {
    "南京": ["中山陵(免费,建议早9点前到)", "夫子庙-秦淮河(夜景,小吃集中)", 
             "南京博物院(免费,需预约)", "明孝陵(钟山风景区)", "老门东(美食街)"],
    "杭州": ["西湖(免费,环湖骑行)", "灵隐寺", "河坊街(小吃)", "宋城", "西溪湿地"],
    "北京": ["故宫(需提前预约)", "颐和园", "南锣鼓巷", "798艺术区", "天坛"],
    # ... 按需扩展
}
```
若搜索失败→降级用本地攻略 + 天气数据生成行程,**Demo 保证能跑通**。

**兜底 2:面试前预查**:面试前一天,对可能用到的城市实际搜一次,确保结果质量,有异常提前替换。

### 7.4 结果标注来源（呼应 RAG 防幻觉设计）

生成行程时,给景点和美食标注来源,与 RAG 管线的 `（来源：xxx，第X页）` 设计保持一致:

```
推荐路线:
  Day1 中山陵(📌来自马蜂窝攻略)→明孝陵→夫子庙
        晚餐 鸭血粉丝汤(📌来自小红书美食推荐)
  Day2 南京博物院(📌来自携程攻略,需预约)→...
```

**面试加分**:面试官会注意到——你在所有 LLM 生成场景(知识库问答 / 行程规划)都设计了引用标注,防幻觉不是某一个模块的补丁,而是**贯穿整个项目的设计原则**。
