# 河海大学信息门户接入方案

> 本文档规划如何用 MCP Agent 对接河海大学信息门户(my.hhu.edu.cn),实现课表查询、成绩查询、教务通知等自动化。使用了不需要官方API的情况下模拟浏览器登录+抓取页面的**Web Scraping + MCP 工具封装**模式。

---

## 一、目标系统分析

**门户地址**:`https://my.hhu.edu.cn/portal-web/guest/hhdx/index.html`

**技术特征**(通过 HTTP 探测获得):
| 特征 | 发现 |
|------|------|
| Web 服务器 | nginx/1.22.1 |
| 前端框架 | HandleBars 模板引擎 + jQuery 风格 JS |
| 认证方式 | Cookie 会话(`pw_route`),未登录跳转 guest 页 |
| 登录入口 | JS 函数 `loginToIndex()`,点击后跳转统一认证页 |
| 内部 API | `/portal-web/api/proxy/...` 存在代理接口 |
| 教务系统 | 作为门户内嵌入式版块,登录门户后通过内部跳转访问 |

**核心判断**:这是一个典型的**国内高校统一门户**——单点登录(SSO)→ 门户聚合各业务系统(教务/图书馆/一卡通等)。教务系统不是独立站点,而是门户内的一个嵌入式服务。

## 三、登录流程分析(最关键的环节)

### 3.1 已确认的全部参数(通过 F12 抓包)

| 层级 | 关键信息 |
|------|---------|
| **CAS 认证** | `authserver.hhu.edu.cn`，AES 加密密码(pwdEncryptSalt)，参数 `username`/`password` |
| **门户** | `my.hhu.edu.cn`，cookie：`JSESSIONID`、`pw_route` |
| **教务系统** | `jwxt.hhu.edu.cn`，cookie：`bzb_jsxsd`、`SERVERID` |
| **课表接口** | `POST /jsxsd/xskb/xskb_list.do`，参数 `xnxq01id`(学期)、`zc`(周次)、`kbjcmsid`，返回 **HTML** |

| CAS 参数 | 值 | 说明 |
|------|-----|------|
| **CAS 登录页** | `https://authserver.hhu.edu.cn/authserver/login` | 统一认证服务器 |
| **回调 service** | `https://my.hhu.edu.cn/portal-web/j_spring_cas_security_check` | 登录成功后 CAS 回调门户验证 ticket |
| **用户名参数** | `username` | 学号 |
| **密码参数** | `password` | **AES 加密后提交**(见 3.2) |
| **加密盐** | `pwdEncryptSalt` | 每次刷新登录页动态生成,隐藏在页面 `<input>` 中 |
| **固定隐藏字段** | `_eventId=submit`, `cllt=userNameLogin`, `dllt=generalLogin`, `execution=e1s1`, `lt=`(空), `captcha=`(空) | 防 CSRF 的标准 CAS 字段 |
| **ticket 参数** | `ticket` | CAS 回调时附在 URL 上 |
| **会话 Cookie** | `JSESSIONID`(CAS 侧), `pw_route`(门户侧) | 登录后保持会话 |

### 3.2 登录流程(精确版)

```
① GET https://authserver.hhu.edu.cn/authserver/login
     ?service=https://my.hhu.edu.cn/portal-web/j_spring_cas_security_check
   → 返回登录页 HTML
   → 从中提取: pwdEncryptSalt(隐藏 input)、execution 值、JSESSIONID cookie

② POST https://authserver.hhu.edu.cn/authserver/login
     ?service=https://my.hhu.edu.cn/portal-web/j_spring_cas_security_check
   Body:
     username=学号
     password=AES加密后的密码(base64)
     pwdEncryptSalt=<①提取的盐>
     _eventId=submit
     cllt=userNameLogin
     dllt=generalLogin
     execution=<①提取的>
     lt=
     captcha=
   Cookie: JSESSIONID=<①获取的>
   → 302 → Location 包含 ticket=ST-xxxx

③ GET https://my.hhu.edu.cn/portal-web/j_spring_cas_security_check?ticket=ST-xxxx
   → 302 → 门户首页(门户验证 ticket → Set-Cookie: pw_route)
   → 此后所有请求带 pw_route cookie 即可访问门户内各版块
```

### 3.3 AES 密码加密(核心难点)

CAS 登录页**不直接提交明文密码**,而是在前端用 AES 加密后再提交。需要找到 CAS 服务器自带的加密 JS。

**定位加密函数的方法**(你来执行,5分钟):

1. F12 打开登录页 → Sources 标签
2. 搜索 `encrypt` 或 `AES` 或 `pwdEncryptSalt`
3. 大概率在 `/authserver/js/` 或 `/authserver/resource/` 下有一个加密 JS 文件
4. 把那个 JS 文件的内容给我(通常几十行,是标准的 AES-CBC 封装)

**备选方案**(如果找不到 JS):

通过浏览器的 Network 标签看登录时 POST 出去的 `password` 字段长什么样:
- 如果是一长串 base64(如 `aGVsbG8...`),确认是 AES-CBC + PKCS7 padding
- 然后在 Python 端用 `pycryptodome` 库实现同样逻辑,模式大概率是:

```python
from Crypto.Cipher import AES
**已确认的加密算法**(从 CAS 登录页 JS 反推):

```javascript
// JS 源码（已获取）
function encryptPassword(n, f) {          // n=密码, f=pwdEncryptSalt
    return encryptAES(n, f)
}
function encryptAES(n, f) {
    return f ? getAesString(randomString(64) + n, f, randomString(16)) : n
}
function getAesString(n, f, c) {          // n=明文, f=密钥, c=IV
    f = CryptoJS.enc.Utf8.parse(f);       // salt → UTF-8 字节作 key
    c = CryptoJS.enc.Utf8.parse(c);       // 随机16字符 → UTF-8 字节作 IV
    return CryptoJS.AES.encrypt(n, f, {
        iv: c,
        mode: CryptoJS.mode.CBC,
        padding: CryptoJS.pad.Pkcs7
    }).toString()                          // → Base64(密文)
}
// randomString(n): 从 58 个字符集中随机取 n 个字符
var $aes_chars = "ABCDEFGHJKMNPQRSTWXYZabcdefhijkmnprstwxyz2345678"
```

**Python 精确翻译**:

```python
import secrets
import base64
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

_AES_CHARS = "ABCDEFGHJKMNPQRSTWXYZabcdefhijkmnprstwxyz2345678"

def _random_string(n: int) -> str:
    return ''.join(secrets.choice(_AES_CHARS) for _ in range(n))

def encrypt_password(password: str, salt: str) -> str:
    """完全对应 CAS 登录页的 encryptPassword()。
    
    salt = pwdEncryptSalt(登录页隐藏input的值)
    返回: Base64(AES-CBC(random64+密码, key=salt_utf8, iv=random16_utf8))
    """
    key = salt.strip().encode("utf-8")              # CryptoJS.enc.Utf8.parse(salt)
    iv = _random_string(16).encode("utf-8")         # CryptoJS.enc.Utf8.parse(randomString(16))
    plaintext = _random_string(64) + password       # randomString(64) + n

    # AES-CBC, key长度决定 AES-128/192/256, pycryptodome 自动
    # 若 key 不是 16/24/32 字节,取前 16 字节(最常见 CAS salt 就是 16 char)
    if len(key) not in (16, 24, 32):
        key = key[:16]  # 安全截断,绝大多数 CAS 盐就是 16 字符

    cipher = AES.new(key, AES.MODE_CBC, iv)
    encrypted = cipher.encrypt(pad(plaintext.encode("utf-8"), AES.block_size))
    return base64.b64encode(encrypted).decode()     # .toString() → Base64
```

### 3.4 代码实现(基于已确认的 CAS 参数)

```python
# tools_edu.py
import httpx
import re
from bs4 import BeautifulSoup

class HuleSession:
    """河海大学信息门户会话,管理 CAS 登录态和教务数据获取"""

    CAS_LOGIN = "https://authserver.hhu.edu.cn/authserver/login"
    CAS_SERVICE = "https://my.hhu.edu.cn/portal-web/j_spring_cas_security_check"

    def __init__(self, student_id: str, password: str):
        self.student_id = student_id
        self.password = password
        self.client = httpx.AsyncClient(
            timeout=30.0,
            follow_redirects=False,  # 手动跟踪,精确控制每一步
            headers={"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                     "AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"}
        )

    async def login(self) -> bool:
        """CAS 登录 → 拿到门户 cookie。
        
        三步:
          ① GET CAS 登录页 → 提取 pwdEncryptSalt / execution / JSESSIONID
          ② POST 账号+AES加密密码 → 302 → 获取 ticket
          ③ GET ticket 回调 → 302 → 门户首页(pw_route cookie 自动保存)
        """
        # ① 获取登录页
        r1 = await self.client.get(
            self.CAS_LOGIN,
            params={"service": self.CAS_SERVICE}
        )
        salt, execution = self._extract_cas_params(r1.text)

        # ② 提交登录
        enc_pwd = encrypt_password(self.password, salt)  # AES 加密(见 3.3)
        r2 = await self.client.post(
            self.CAS_LOGIN,
            params={"service": self.CAS_SERVICE},
            data={
                "username": self.student_id,
                "password": enc_pwd,
                "pwdEncryptSalt": salt,
                "execution": execution,
                "_eventId": "submit",
                "cllt": "userNameLogin",
                "dllt": "generalLogin",
                "lt": "",
                "captcha": "",
            },
        )
        ticket_url = r2.headers.get("Location", "")
        ticket = self._extract_ticket(ticket_url)
        if not ticket:
            return False

        # ③ 验证 ticket → 拿到 pw_route cookie
        await self.client.get(
            self.CAS_SERVICE,
            params={"ticket": ticket},
        )
        return "pw_route" in str(self.client.cookies)

    def _extract_cas_params(self, html: str) -> tuple[str, str]:
        """从 CAS 登录页提取 pwdEncryptSalt 和 execution"""
        salt = ""
        exec_val = ""
        m = re.search(r'id="pwdEncryptSalt"\s+value="([^"]*)"', html)
        if m: salt = m.group(1)
        m = re.search(r'name="execution"\s+value="([^"]*)"', html)
        if m: exec_val = m.group(1)
        return salt, exec_val

    def _extract_ticket(self, url: str) -> str:
        """从重定向 URL 提取 ticket=ST-xxx"""
        m = re.search(r'ticket=(ST-[^&\s]+)', url)
        return m.group(1) if m else ""

    # ... 登录代码同上 ...

    # ── 教务数据获取 ─────────────────────────────────

    JWXT_BASE = "https://jwxt.hhu.edu.cn/jsxsd"

    async def fetch_schedule(self, xnxq01id: str = "", zc: str = "") -> str:
        """获取课表 HTML → 解析 → 格式化返回。

        POST /jsxsd/xskb/xskb_list.do
        参数: xnxq01id(学期ID,空=当前学期), zc(周次,空=当前周)
        """
        if not await self.check_session():
            return "❌ 教务系统登录已失效，请重新登录"

        url = f"{self.JWXT_BASE}/xskb/xskb_list.do"
        data = {
            "xnxq01id": xnxq01id or "",
            "zc": zc or "",
            "kbjcmsid": "",   # 留空=默认课表模板
        }
        # 请求课表页面时带 Referer(从主框架跳转)
        headers = {
            "Referer": f"{self.JWXT_BASE}/framework/xsMain_hehdx.htmlx",
        }
        r = await self.client.post(url, data=data, headers=headers)
        return parse_schedule_html(r.text)

    async def fetch_grades(self, xnxq01id: str = "") -> str:
        """获取成绩(接口模式与课表相同,URL 替换为 /xscj/xscj_list.do)"""
        # TODO: 确认成绩页面的实际 POST URL 和参数后补全
        pass
```

### 3.5 课表 HTML 解析(lxml/BeautifulSoup)

课表返回的是传统 `<table>` 格式:行=节次,列=周一~周日。

```python
from bs4 import BeautifulSoup

def parse_schedule_html(html: str, weekday: str = "") -> str:
    """解析 jsxsd 课表页面 HTML → 自然语言文本。

    课表结构:
      <table id="kbtable"> 或 class 含 "kbtable"
        <tr> <th>节次</th> <th>周一</th> <th>周二</th> ... </tr>
        <tr> <td>1-2节</td> <td>通信原理<br>教3-201<br>张老师</td> ... </tr>
    """
    soup = BeautifulSoup(html, "lxml")
    table = soup.find("table", id="kbtable") or soup.find("table")
    if not table:
        return "未找到课表数据(可能需要调整学期/周次参数)"

    rows = table.find_all("tr")
    if len(rows) < 2:
        return "课表为空(是否还没选课?)"

    # 表头确定列映射: 节次 | 周一 | 周二 | ...
    header_cells = rows[0].find_all(["th", "td"])
    day_names = []
    for cell in header_cells:
        t = cell.get_text(strip=True)
        day_names.append(t if "节" not in t else "")

    result_lines = []
    for row in rows[1:]:
        cells = row.find_all("td")
        if not cells:
            continue
        period = cells[0].get_text(strip=True)  # 节次,如 "1-2节"
        for i in range(1, len(cells)):
            text = cells[i].get_text(separator=" | ", strip=True)
            if text:
                day = day_names[i] if i < len(day_names) else f"第{i}列"
                result_lines.append(f"{day} {period}  {text}")

    if not result_lines:
        return "课表为空"
    return "\n".join(sorted(result_lines))  # 按周几+节次排序
```

## 五、HTML 解析策略(课表/成绩)

国内教务系统的课表通常是 `<table>` 格式:

```html
<table>
  <tr><th>节次</th><th>周一</th><th>周二</th>...</tr>
  <tr><td>1-2节</td><td>通信原理\n教3-201\n张老师</td><td></td>...</tr>
  <tr><td>3-4节</td><td></td><td>数字信号处理\n实验楼A\n李老师</td>...</tr>
</table>
```

**解析代码**(BeautifulSoup,约 30 行):

```python
from bs4 import BeautifulSoup

def parse_schedule_html(html: str, weekday: str = "") -> str:
    soup = BeautifulSoup(html, "lxml")
    table = soup.find("table", {"class": "schedule"})  # class 名需 F12 确认
    rows = table.find_all("tr")[1:]  # 跳过表头

    weekday_map = {"周一": 1, "周二": 2, "周三": 3, "周四": 4, "周五": 5}
    target_col = weekday_map.get(weekday) if weekday else None

    result = []
    for row in rows:
        cells = row.find_all("td")
        period = cells[0].get_text(strip=True)  # 节次
        for i, cell in enumerate(cells[1:], 1):
            if target_col and i != target_col:
                continue
            text = cell.get_text(separator="\n", strip=True)
            if text:
                result.append(f"{period} | 周{i} | {text}")
    return "\n".join(result) if result else "该时段无课程"
```

或者如果课表页面有 JSON 接口(很多现代教务系统 /api 会返回 JSON),直接用 `resp.json()`,连 BeautifulSoup 都省了——**这是最理想的情况,F12 时优先找有没有 XHR 请求**。

## 十、统一接入模式 —— 一行 URL 接一个业务系统

> 河海信息门户内有**多个嵌入式服务**(教务/成绩/一卡通/图书馆/校园通知/报修等),它们共享同一套 CAS 认证。`HuleSession` 的 `login()` 和 `_follow_js_redirects()` 是**所有服务的统一认证层**。

### 10.1 核心原理

河海门户采用 **CAS 统一认证**:
1. 用户只需登录一次(输入学号+密码)
2. CAS 签发 TGT(Ticket Granting Cookie)
3. 访问任何受保护服务 → 自动跳转 CAS → CAS 发现已有 TGT → 签发新 ST → 回到目标服务 → 目标服务设自己的 session cookie

**关键**:不同服务(jwxt / card / lib)只需要经过同一个 `_follow_js_redirects()` 流程,就能各自拿到该域名的 session cookie。**登录代码零重复**。

### 10.2 三步公式(加一个服务 ≈ 写一个函数)

```
新服务接入 = URL + 解析函数 + @mcp.tool()注册
              ↑         ↑            ↑
           F12抓包   与课表同模式   15行模板代码
```

**模板代码**(以成绩查询为例,粗体为唯一不同的部分):

```python

## 十一、实现过程中遇到的问题与解决方法

以下是在实际编码和调试过程中遇到的真实问题,按发现顺序排列。

### 问题 1：AES 加密算法逆向

**现象**:CAS 登录提交时需要 AES 加密密码,但加密逻辑在前端 JS 中,Python 端没有现成 SDK。

**排查过程**:F12 抓取 CAS 登录页的 JS 源码(约 740 行混淆代码)→ 定位到 `encryptPassword()`→ 追踪调用链 `encryptPassword → encryptAES → getAesString`→ 确认算法为 **AES-CBC + PKCS7**,密钥=`pwdEncryptSalt` 的 UTF-8 字节,IV=`randomString(16)` 的 UTF-8 字节,明文前加 64 位随机前缀。

**解决方法**:用 `pycryptodome` 库精确翻译 JS 加密逻辑为 Python `encrypt_password()`,包括随机字符集(`$aes_chars` 58 个字符)、key/IV 编码方式、OpenSSL Base64 输出格式。**不需要任何 JS 运行时**,纯 Python 即可。

### 问题 2：JS 重定向 vs HTTP 302

**现象**:登录门户后,访问教务系统(`jwxt.hhu.edu.cn`)时,httpx 跟随 HTTP 302 后只拿到 163 字节的 JS 脚本,无法继续跳转。

**排查过程**:对比浏览器行为——浏览器地址栏会短暂显示 `sso.jsp` 然后跳到 `xsMain_hehdx.htmlx`,说明发生了两次跳转。但 httpx 只跟了第一次 HTTP 302。检查 163 字节的响应内容:
```html
<script>window.location.href='https://authserver.hhu.edu.cn/authserver/login?service=...'</script>
```

**关键发现**:`sso.jsp` 使用 **JavaScript 重定向**(`window.location.href=`)而非 HTTP 302/301。httpx 的 `follow_redirects=True` **只跟随 HTTP 重定向,不执行 JavaScript**。

**解决方法**:新增 `_follow_js_redirects()` 方法,正则提取 JS 中的 `window.location.href='...'`,手动跟随(最多 5 跳),直到拿到真实页面(>500 字节)。

### 问题 3：课表 HTML 中课程数据为 display:none

**现象**:成功拿到课表 HTML(62KB),但所有课程单元格的 div 都是 `style="display:none"`,BeautifulSoup 提取不到任何课程名称。

**排查过程**:
1. 第一反应:数据是 AJAX 异步加载的 → 尝试找 XHR 接口,未找到
2. 然后尝试 GET `?type=ajax` 参数 → 返回同样的 HTML
3. 怀疑是暑假没课 → 用户确认浏览器端也是空壳
4. **关键突破**:改用 `xnxq01id='2024-2025-2'` 指定上学期后,div 中出现实际课程数据

**根因**:不是 JS 异步加载,也不是 `display:none` 隐藏,而是**暑假当前的默认学期根本没有排课数据**,所有 div 都是空的。换成有课的学期后,'display:none' 的 div 里也包含了完整的课程信息——JS 只是切换可见性,数据始终在 HTML 里。

### 问题 4：课表 HTML 结构复杂,正则/简单解析失效

**现象**:拿到有数据的 HTML 后,原始的按 `<td>` 文本直接提取的解析逻辑无法正确提取课程名、教师、周次、教室。

**实际数据结构**(远比预想的复杂):
```
数字电子技术齐本胜1-12(周)[1-2节]【2号楼C区】2号楼C区2号楼C区C217通知单编号：202420252050185班级：通信23-[5-6]班备注：(理论:48)
```
课程名、教师名、周次、教室、通知单编号、班级信息**全部混在一行文本里**,没有任何标签分隔。

**解决方法**:用正则逐字段提取:
- 教师:`([一-鿿]{2,4})(\d+-\d)` → 2-4 个汉字后紧接数字(周次)
- 节次:`\[(\d+-\d+节)\]`
- 教室:`【(.+?)】`
- 课程名:取教师名前的部分并去掉数字

### 问题 5：同一单元格多 div 导致课程重复

**现象**:课表输出中,每门课出现两次——一条简短(只有课程名)、一条详细(含教师/周次/教室)。

**原因**:课表每个 `<td>` 内有 3 个 `kbcontent` 类 div(分别对应不同显示模式:单周/双周/全周),同一课程可能出现在多个 div 中。

**解决方法**:按 `(星期+节次)` 作为 key 去重,**保留信息量最大**(文本最长)的那条。

### 问题 6：multi-cookie 冲突

**现象**:登录成功后,访问教务系统时 httpx 报 `CookieConflict: Multiple cookies exist with name=JSESSIONID`。

**原因**:CAS 认证服务器(`authserver.hhu.edu.cn`)、门户(`my.hhu.edu.cn`)、教务系统(`jwxt.hhu.edu.cn`)三个不同域名各自发了一个 `JSESSIONID` cookie。httpx 的 CookieJar 将它们合并时产生冲突。

**解决方法**:接受冲突是正常的(不同域名本身就该有不同的 JSESSIONID)。在关键请求上使用 `follow_redirects=True` 让 httpx 自动按域名匹配 cookie;调试验证时避免 `dict(cookies)` 强转,改用逐个遍历。

### 问题 7：校园网 SSL 间歇中断

**现象**:到 `authserver.hhu.edu.cn` 的 HTTPS 请求经常报 `SSL: UNEXPECTED_EOF_WHILE_READING`,但浏览器访问正常。

**原因**:校园网内网环境,SSL 握手偶发中断(可能是负载均衡/中间件问题)。

**解决方法**:
1. `verify=False` 跳过 SSL 证书验证(本地使用,安全可控)
2. `login()` 内置 3 次重试 + 递增间隔(0.5s/1s/1.5s)

### 问题 8：推理模型 max_tokens 陷阱(项目通用坑,非本次独有)

**现象**:与本次接入无关,但本项目的 LLM 调用(`deepseek-v4-flash`)在短输出场景(如翻译、改写)下偶发返回空 content。

**原因**:该模型是推理模型,先输出 `reasoning_content` 再出正式 `content`。`max_tokens` 过小(<120)时,token 被推理过程耗尽,正式输出为空。

**与本次接入的关系**:教务系统的 LLM 调用(Agent 决策/回答生成)使用 `max_tokens=4000`,不受影响。但项目中已有的查询翻译(`max_tokens=50`)和查询改写(`max_tokens=120`)之前被此问题影响,已在本轮开发中统一修到 ≥512。
